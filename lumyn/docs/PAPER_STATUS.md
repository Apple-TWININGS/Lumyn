## 一、核心主张（拟）

> **当生成任务带有可解析的守恒量时，守恒律验证器可以承担 critic 的角色，
> 提供比学出来的 critic 更低成本、更可复现、且跨分布更稳健的监督信号。**

这是**范式级**主张，不是方法增量。它可证伪：若守恒律 critic 在跨分布上
不优于学习式 critic，则命题失败。

理论骨架与实验设计详见 `docs/RESEARCH_DIRECTION.md`。

## 三、两个必须先解决的硬伤

### 硬伤 1：表 3 是硬编码常数（学术诚信问题）

`lumyn/explain/causal_tracing.py`：

```python
# _run() 与 _run_restore() 内
base  = {"galaxy": 0.85, "collision": 0.80, "explosion": 0.75}.get(scene_type, 0.70)
decay = {"director": 0.12, "generate": 0.30, "validate": 0.55}
```

代码里其实**自己写了注释承认是占位**：
> `# 轻量模拟：真实接入时替换为 engine.generate_scene(...)`

但 README 把它呈现为「真实数字（来自 `CausalTracer.trace()`）」，
并据此得出「验证层贡献度 >50%，是论文中最有力的证据」。

**且两套数字互相矛盾**：README 写 galaxy = 0.12/0.35/0.53，
代码常数是 0.12/0.30/0.55。两套都是编的。

**处理方案（选定 A：真做）**：
实现真实的逐层 corruption → 跑完整管线 → 用 SimScore 量
clean / corrupt / restore 三种条件下的物理正确性 → 算差值。

### 硬伤 2：导演层未接入生成路径

`core/engine.py::LumynEngine.generate` 的实际实现是：

```python
scene = presets.get(scene_type, **kwargs)
traj, mass = scene.run(steps=steps)
validation = self.validator.diagnose(traj, mass, dt=scene.dt)
```

**没有 director**。`core/director.py` 存在，但不在 `generate` 的调用链上。

**后果**：
1. README 描述的「三层管线」与实际代码路径不符（实际只有两层）
2. 因果追踪无法对导演层做有意义的损坏——因为它不参与生成

**处理方案（二选一）**：
- **A1**：把 director 真正接入 `generate`，使三层管线名副其实，再做三层追踪
- **A2**：如实把管线改为「两层（生成 + 验证）」，追踪只报两层

> 建议 A1：LLM 导演层是 Lumyn 相对普通 N 体模拟器的差异化所在，
> 去掉它论文会弱很多。但接入前不得声称「三层」。

## 四、真实因果追踪的设计（待实现）

对**实际存在**的层做真实损坏：

| 层 | 真实损坏方式 | 预期 |
|---|---|---|
| **generate** | ① 给轨迹加噪 ② 劣化积分器（切回显式欧拉 / 增大 dt） | SimScore 下降 |
| **validate** | 禁用守恒门控（保留诊断为纯观测、不回退不重生成） | 物理不一致的结果被放行 |
| **director** | 损坏物理定律序列（需先接入，见硬伤 2） | 场景语义偏离 |

**三条件定义**（对齐 PhysBench 的语义）：
- `clean`：三层全干净
- `corrupt(k)`：只损坏第 k 层，其余干净 → 退化分
- `restore(k)`：损坏其余层、只恢复第 k 层 → 恢复分
- **贡献度(k) = restore(k) − all_corrupt**（全坏基线）

**必须报告**：每个条件的均值 ± 95% CI、重复次数、以及损坏强度的敏感性。
