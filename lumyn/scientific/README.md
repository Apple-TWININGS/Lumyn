# `lumyn/scientific/`

A reproducible astrophysics and N-body module for research visualization and teaching.

This module does not generate videos that merely look like galaxies. It numerically
integrates a real gravitational N-body system and renders the result, so every frame
corresponds to a trajectory that can be recomputed from explicit parameters.

It does **not** aim for the accuracy of dedicated N-body codes (NBODY6, REBOUND with
Hermite or IAS15). The intended level is credible research visualization and teaching.

---

## Verified capability

| Statement | Evidence |
|-----------|----------|
| Scenes are generated by a Barnes-Hut tree plus velocity Verlet integration | `physics/nbody.py` |
| Trajectories are bit-for-bit reproducible for a fixed seed | determinism test in `tests/test_scientific.py` |
| The `binary_star` preset conserves energy to ~1e-8 relative drift over 10 steps | measured below |
| Trajectories export to CSV and render to MP4 | `tests/test_scientific.py` |

> Correction of a previously stated claim. Earlier versions of this document asserted
> that all four presets keep total energy drift below 1%, citing an assertion
> "`drift <= 0.02`" in `test_scientific.py`. **No such assertion exists.** The test file
> only checks that the returned diagnostics dictionary contains the keys
> `energy_drift` and `angular_momentum_drift`; it applies no threshold to either. That
> claim has been removed rather than weakened, because the underlying measurement was
> never performed across all four presets.

## Scenes

| Preset | Physical setup | Notable fields |
|--------|----------------|----------------|
| `binary_star` | Two-body Kepler, mass ratio 3:1 | `m1`, `m2`, `separation` |
| `spiral_galaxy` | Exponential disk with velocity dispersion | `omega` |
| `globular_cluster` | Plummer-like isotropic cluster | |
| `galaxy_collision` | Two spiral galaxies on a close approach | `center_offset` |

`presets.get(name, **kwargs)` returns a `SceneParams` object. `SceneParams.run(steps)`
evolves the scene and returns a `(trajectory, mass)` tuple, where the trajectory has
shape `(steps + 1, n_particles, 3)`.

> The functions are `presets.get()`, `presets.binary_star()`, `presets.spiral_galaxy()`,
> `presets.globular_cluster()` and `presets.galaxy_collision()`. Earlier documentation
> referred to `presets.load()` and `presets.get_preset()`; neither exists.

## Working example

Verified on this checkout:

```python
from lumyn.scientific import presets, metrics

params = presets.get("binary_star", n_particles=50)
trajectory, mass = params.run(steps=10)

mt = metrics.PhysicsMetrics(G=params.G)
print(trajectory.shape)                       # (11, 50, 3)
print(mt.energy_drift(trajectory, mass))      # 8.685500968250139e-09
```

`PhysicsMetrics.diagnose(trajectory, mass, dt)` returns a dictionary with the keys:

```
energy_drift, energy_final, energies,
angular_momentum_drift, angular_momenta,
com_drift, half_mass_radius_final, half_mass_radius_shrink
```

## Module map

| File | Class or function | Purpose |
|------|-------------------|---------|
| `presets.py` | `SceneParams`, `get()`, and four scene constructors | Scene definition and evolution |
| `metrics.py` | `PhysicsMetrics`, `energy_drift()`, `momentum_conserved()` | Energy, angular momentum, center of mass, half-mass radius |
| `export.py` | `ScientificExporter.to_csv()`, `.to_fits()` | Trajectory export (FITS requires astropy) |
| `visualization.py` | `ScientificVisualizer.render_3d()`, `.render_2d_with_physics()` | Rendering, with point size mapped to mass and color to speed |
| `frames.py` | `FrameExtractor.extract()`, `.make_grid()` | Frame extraction and contact sheets |
| `teaching.py` | `TeachingMode.compare_mass()`, `.compare_angular_velocity()` | Side-by-side parameter comparison |
| `differentiable.py` | `DifferentiableNBody`, `ConservationConstraint` | PyTorch differentiable N-body path |

Note the interface shapes, which differ from what earlier documentation implied:

- `PhysicsMetrics.__init__` takes only `G`. Trajectory and mass are passed to each method.
- `ScientificExporter.to_csv(trajectories, output_path, ...)` and
  `ScientificVisualizer(trajectories, metadata=None)` expect a **dictionary** of
  trajectories, not a bare array.

## Two different classes named `DifferentiableNBody`

There are two distinct implementations sharing this name:

| Module | Style | Constructor |
|--------|-------|-------------|
| `lumyn/physics/differentiable.py` | Takes initial conditions directly; `pos`, `vel`, `mass` become `nn.Parameter` | `DifferentiableNBody(pos, vel, mass, ...)` |
| `lumyn/scientific/differentiable.py` | `nn.Module` that takes configuration only and is given state at call time | `DifferentiableNBody(G=1.0, softening=0.05, dt=0.01, ...)` |

The `scientific` variant exposes `simulate()`, `step()`, `acceleration()`, `energy()`
and `angular_momentum()` as static methods, plus `optimize_initial_conditions()` and
`contact_map()`. The `physics` variant is documented in `physics/README.md`.

The `scientific` variant also has a known defect: it passes NumPy arrays to
`torch.Tensor.unsqueeze` in `acceleration()`, raising
`AttributeError: 'numpy.ndarray' object has no attribute 'unsqueeze'`. This is what
breaks `examples/scientific_demo.py`.

## Limitations

1. **Barnes-Hut approximation.** Multipole expansion at `theta=0.5` introduces O(theta^2)
   error relative to an exact O(N^2) sum. Reduce `theta` or use direct summation when
   accuracy matters.
2. **Softening** avoids small-distance singularities but slightly alters the energy of
   tightly bound pairs. It is not appropriate for extreme black-hole / particle cases.
3. **Conservation analysis requires float64.** Rendering defaults to float32.
   In float32, rounding dominates the measured drift.
4. **Float32 rendering and float64 analysis are separate paths**; do not compare drift
   numbers across them.
5. **Scale.** Current tests use tens to hundreds of particles. Beyond roughly 1000
   particles, a Barnes-Hut tree plus GPU execution is required.
6. **The relativistic term is an approximation.** The Lorentz factor is valid only in the
   weak-field limit. Strong-field cases need a general-relativistic solver.
7. **Noisy diagnostics are not available.** `lumyn/explain/causal_tracing.py` returns
   hard-coded constants rather than measurements. Any per-layer contribution figure
   attributed to it is fabricated; see the top-level README.

## Running the tests

```bash
python -m unittest lumyn.tests.test_scientific -v
```

12 tests, covering export, rendering, teaching, presets and the NumPy differentiable
path. One additional test is skipped when `astropy` is not installed.
